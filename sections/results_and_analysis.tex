\section{Fidelity Checks}
\label{sec:results}
\label{subsec:calibration}

The results proceed in two stages. We first calibrate when SRP accounts are
faithful enough to interpret: the factorized readout must preserve LM-head
behavior, reconstruct selected scores with low error and preserved sign, beat
generic baselines, and admit a target-family regime where local readings hold.
Under those gates, \Cref{sec:readout-analyses} then uses sign-preserved,
low-residual cases to analyze score choice, token preferences, context shifts,
attribution, and edits. Aggregate low-error counts use \(\rho<0.5\).

\subsection{Selected-Score Reconstruction}
\label{subsec:selected-score-reconstruction}

The logit-difference columns test whether selected scores survive the same
factorization. Sign agreement is at least \(0.91\) across the suite, and most
contrasts fall in the sign-preserved, low-error subset (\(\rho<0.5\), with
\(\rho=|s_{\mathrm{exact}}-s_{\mathrm{recon}}|/(|s_{\mathrm{exact}}|+0.5)\)).
Errors and flips concentrate near small exact margins
(\Cref{fig:readout-query-fidelity-result}), so case studies use nontrivial
margins with small residuals. RowEV is a capacity metric, not validation of any
feature bar.

\subsection{Operating Regimes for Local Interpretation}
\label{subsec:operating-regimes}

With the basis fixed, reference-style contrasts and separated margins reconstruct
more reliably than heterogeneous row combinations or near ties
(\Cref{tab:benchmark-derived-task-targets,tab:app-general-readout-query-families};
Appendix~\ref{app:readout-target-family-display-example}). Later displays stay
in that regime and are read only when sign is preserved and residual is small.

\section{Readout Analyses}
\label{sec:readout-analyses}

Within the calibrated regime, we ask what SRP adds to a logit-lens preference,
how the chosen readout question changes the account, which features carry
token preferences, how context reweights fixed-token projections, and whether
the same terms compose with residual-stream attribution and constrained
readout-side edits.

\subsection{From Logit-Lens Preferences to Sparse Readout Accounts}
\label{subsec:lens-to-sparse-account}

Lens-style readouts identify a favored token or contrast but leave it as a dense
LM-head dot product. In \Cref{fig:main-lens-prism-comparison}, SRP holds the
\texttt{verify}-minus-\texttt{assume} score fixed and decomposes that same
preference into signed readout terms plus an explicit residual. The object
changes from an atomic lens score to a residual-checked sparse account in logit
units: positive and negative terms support or oppose the selected side. This is
still a readout-level account; behavioral or causal claims require separate
tests.

\subsection{Score Choice Determines Support and Opposition}
\label{subsec:target-choice}

A large projection onto a readout feature is not intrinsically favorable or
unfavorable: its sign depends on whether the selected score uses that feature
more on the target side or the comparison side. Selected-direction coefficients
turn projections into signed contributions, so a feature may support a raw
logit, drop out after mean subtraction, or become negative when the comparison
token uses it more. Each display must therefore name its selected score, since
changing \(q\) changes \(\beta_i(q)\) and the same projection vector can yield
different support and opposition terms.
\Cref{subsec:calibration} bounds which choices of \(q\) admit such comparisons.

\subsection{Logit Differences Reveal Competing Readout Features}
\label{subsec:feature-competition}

Sign-preserved, low-error local decompositions identify which readout features
raise or lower token-vs-token scores within a ranking. Using the fixed SRP
basis, we decompose low-error Qwen3.5-2B polysemous-token logit differences
(\Cref{fig:selected-readout-prism-examples}). In an insect context,
\texttt{bug} draws positive mosquito-, bee-, and beetle-labeled terms against
error-token rows; in software, positives shift toward defect, crash, and debug
rows. The panels have relative errors \(0.185\) and \(0.003\). Additional
\texttt{bark}/\texttt{bass} cases, plotting conventions, and label audits
appear in
\cref{fig:app-selected-readout-prism-extra-examples,app:display-taxonomy,tab:app-main-case-study-feature-audit}.
The same surface token draws support from different row-labeled feature groups
as the selected score and context change.

\subsection{Prompt Context Reweights Fixed Token-Row Features}
\label{subsec:context-reweighting}

Holding the selected token row fixed isolates context effects: token-row
coefficients stay fixed, while hidden-state projections \(h^\top d_i\) change.
In \Cref{fig:same-token-polysemy}, prompt context reweights \texttt{bug},
\texttt{ring}, and \texttt{bridge} toward features whose row labels match the
setting; each offset-subtracted token score has \(\rho<0.05\). \texttt{bug}
shifts from mosquito/bee to defect/crash/debug labels, and \texttt{bridge}
from river/crossing to networking labels. These cases separate the
context-independent component of a local account, carried by the token-row
coefficients, from the context-dependent component, carried by hidden-state
projections onto the readout feature directions. Additional views are in
Appendix~\ref{app:additional-qwen-display-examples}.

\subsection{Feature-Resolved Component Attribution}
\label{sec:feature-resolved-component-decomposition}
\label{subsec:feature-resolved-component-attribution}

Signed readout terms are linear in the final hidden state, so additive
residual-stream decompositions can pass through the fixed SRP basis. We compose
SRP with direct logit attribution (DLA)
\citep{elhage2021framework,wang2022ioi,nguyen2024logitprisms}: if
\(h\approx\sum_c h_c\), a feature term for selected direction \(q\) splits into
\[
    M_{c,i}(q)=\beta_i(q)\,h_c^\top d_i .
\]
This is component-by-feature accounting for a realized forward pass, not causal
necessity without interventions \citep{geiger2023causalabstraction}.

\Cref{fig:qwen-prism-dla-verify-assume-main} decomposes a Qwen3.5-2B

assumption-family opposition. A row-centered companion appears in
Appendix~\ref{app:feature-resolved-dla}.
